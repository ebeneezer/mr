American Cybernetics (makers of Multi-Edit) went out of business in 2020 and stopped development of the TUI version of Multi-Edit years bevor.

Mr is a rewrite of the classic programmers editor Multi-Edit by American Cybernetics for Linux terminals. It is constructed aroud a macro language processor, that compiles macro files based on the MEMAC script language.
Now called MRMAC the language is backwards code compatible towards the MEMAC dialect but renewed and extended for modern systems.
Compilation happens in-RAM through the MRMAC compiler that supports both precompiled and on-demand compiled macro files for maximum speed.

Dependencies:
  - the Turbo Visison C++ rewrite TVISION from magiblot on GitHub. TVISION can also be steered from mrmac macros - just like it was in the old days with Multi-Edit
  - advanced data processing models like piecetables, addbuffers, tries and more to edit files
    larger than system memory and provide file I/O with blazing speed: It loads 1 GB text und
    under one single second und indexes the whole text in under 800 milliseconds (no BS)
  - a build in coprocessor for handling mrmac bytecode macros that can manipulate text in parallel
    to the user in the same window (no BS). The coprocessor supports running multiple macro jobs
    in parallel in different windows or multiple macrojobs in one window or both at the same time.
    Thecoprocessor uses multiple computes lanes in parallel: I/O, COMPUTE, MACRO and MINIMAP
  - ncursesw and is UTF8 capable

Features (among others):
  - automated syntax highlighting, code folding and smart indenting for all known programming languages (except the marsian X!/&%/:-P language)
  - a macro manager for recording macros and binding them to hotkeys. You can also create, manage, edit and bind .mrmac files from inside the manager
  - virtual desktops
  - workspaces: Loading, saving, autoloading,autosaving, workspace-wide multifile search & replace.
  - a window manager that can tile, minimize and cascade windows
  - recursive multi file search & search and replace
  - full Perl regex PCRE2
  - a sub character minimap display
  - inter window copy & paste and copy & paste with the OS
  - stream block, line blocks and colum blocks including sorting of the marked block
  - an key mapping manager and loadable key mapping to emulate other stateless editors like Emacs, Nano or Wordstar
  - profiles per file extension or group of file extensions: You can setup the handling of code files depending of the code you edit
  - color theme loading and saving from file extension profiles
  - automatic language detection
  - automatic multi-level graphical code folding
  - smart indenting and undenting
  - printing via PDF exports
  - acquire files from the output of shell commands or pipes
  - compiler profiles with automatic setup and error tracking in code
  - hex edit mode with synchonous hex, dec, oct, strings and binary view plus additional data inspector

 KEYBOARD REFERENCE

Shift-F1 opens the detailed Help index.

selected reference, Backspace returns to the previous topic, and Esc closes
the Help window.

current editor mode. They may change for startup, normal editing, file
comparison, compiler diagnostics, and macro debugging.

.topic MenuFile=10
 FILE MENU

Open loads a file in a new editor window. Load replaces the contents of the
current suitable editor window. Get last lists recently used files, folders,
and workspaces. Acquire scans a directory or runs a command and presents the
resulting files for selection.

Open live log follows a text file as it grows. Open journal reads systemd
journal output, optionally filtered by application tag. Open workspace
loads an MR workspace description.

Save writes the current document. Save as selects another URI. Save all
offers to write all modified documents. Info displays document, file, and
editor metadata. Export to PDF opens the PDF export settings. Exit closes
MR after dirty documents and settings have been handled.

Related dialogs: {Get Last:DialogGetLast}, {Acquire:DialogAcquire},

.topic MenuBlock=14
 BLOCK MENU

Copy, Move, and Delete operate on the marked block. Load block reads text
from disk into the block position; Save block writes only the marked block.
Indent and Undent adjust the selected lines by the configured indentation.

Window copy and Window move transfer a block between editor windows.

Mark lines selects complete lines, Mark columns selects a rectangle, and Mark
stream selects a continuous character range. Hide/show block mark changes
only the projection. End marking completes the current mark. Turn marking
off removes it.

MARKING BLOCKS WITH THE MOUSE

In ordinary editing mode (line drawing off), hold the modifiers before
pressing the left mouse button. Drag to the other end, then release:

  Stream:  left-button drag
  Column:  Alt + left-button drag
  Line:    Ctrl+Alt + left-button drag

The highlight follows the pointer. Release commits the block. Either drag
direction works; moving beyond a text-area edge scrolls while marking.
Column blocks include the pointed-to cells at both horizontal ends and use
display columns, including tab widths. Stream blocks end before the end
position. Line blocks include the complete first and last touched lines.

Ctrl + left-button drag explicitly starts a new stream block, including
inside an existing block. An unmodified left-button drag inside an existing
block moves it with a live preview instead: release places it, Esc cancels,
and the completed move is one Undo step. Plain right-click opens the context
menu.

The terminal must forward mouse events and modifiers to MR. If a gesture is
intercepted, use Mark lines, Mark columns, or Mark stream from this menu.

Persistent blocks controls whether a completed block survives cursor movement.
The ON or OFF suffix reports the current runtime setting.

.topic DialogColorSetup=115
 COLOR SETUP

The group field selects a color domain. Every item-list row begins with an
Aa sample rendered in that role's foreground and background colors. The row
selection changes only the description color, so it does not obscure the
sample.

Foreground RGB and Background RGB edit the red, green, and blue components
of the selected role from 0 through 255. The centered RRGGBB/RRGGBB value
shows both exact 24-bit colors. Changes update the item-list sample live.

In HELP COLORS, help-window controls sets the color of the window-button
glyphs and draggable frame corners.

Load Theme reads a theme file into the working color draft. Save Theme writes
the complete draft. Invalid or missing groups use their hardcoded defaults.
The running settings change only when the dialog flow accepts changed data.

Fresh installations use the 256-color terminal palette so that the built-in
BIOS-derived theme retains its ANSI palette-index semantics. Setup can select
automatic 24-bit RGB output instead. Automatic output lets Turbo Vision use
true color where the terminal supports it and perform its normal fallback
otherwise.
Palette mode maps the exact 16 VGA default colors back to their ANSI palette
indices, preserving the terminal's configured classic colors. Other RGB values
are quantized to standard xterm-256 indices. Turbo Vision performs any further
fallback required by terminals with fewer colors.

.topic UserManualPreface=201
 PREFACE

MR is a terminal-native programmer's editor with a window system, a large
document model, configurable editing profiles, and an in-memory macro
language. The application deliberately does not make the user choose
between the immediacy of a text-mode editor and the facilities normally
associated with an IDE. Files, output, searches, workspaces, binary data,
compiler diagnostics, and macros all live in the same TVision desktop.

The original Multi-Edit manual supplied a particularly practical order:
begin with the screen and cursor, proceed through text and blocks, and
only then introduce automation. This book follows that route without
treating the historical program as a specification. DOS shells, printer
drivers, page-break formatters, and other facilities that do not exist in
MR have no chapter here. Their place is taken only where a current feature
solves the same user problem.

The screenshots were taken from real MR sessions in a PTY. They are not
mock-ups. The active colors, available profiles, filenames, and
function-key labels therefore reflect an installed development
configuration; another installation may use a different theme or keymap.
The operation names and dialog structure are the stable part.

This is a task-oriented manual. The MRMAC Reference Manual remains the
authority for language syntax and individual primitives, while the
Technical Manual explains implementation boundaries and performance
design.

.topic UserManualC01S01=203
 1.1 INSTALLING A RELEASE AND CHECKING PREREQUISITES

Run the release package's install.sh as your ordinary user. It checks its
payload and runtime dependencies before installing files, and requests
sudo when the system destination requires it. Existing personal macro
files are preserved. Each additional user runs the installer to initialise
that user's macro directory.

Installation requires a UTF-8 locale. Check locale charmap and the values
of LANG, LC_CTYPE, and especially LC_ALL if the installer rejects the
character map. Fontconfig's fc-list must also find fonts covering the
tape, magnifier, and clock symbols used by the interface. The installer
lists missing codepoints and suggests fontconfig with
fonts-noto-color-emoji on Debian-family systems, or fontconfig with
noto-fonts-emoji on Arch-family systems. Installing a font does not
replace the terminal emulator's own font and fallback configuration.

Missing shared libraries, unavailable runtime symbol versions, and a
failed startup compatibility probe stop installation with an explanation.
The release uses the baseline x86-64 instruction set and targets Debian
12-compatible runtime versions; the installer checks the actual packaged
executable on the receiving machine. GDB is a separate requirement for
debugging compiled programs and must be available on PATH.

.topic UserManualC01S02=204
 1.2 STARTING MR FOR THE FIRST TIME

Start the editor from a terminal with its executable name. A file argument
is optional:

  mr
  mr README.md
  mr src/main.cpp include/main.hpp
  mr notes/new-file.txt

With no file argument, MR opens its desktop and waits for a command. With
one or more paths, every readable file receives an editor window. An
explicit path which does not exist yet opens as an empty, named text
document; saving it creates that file. Unmatched wildcard expressions do
not create documents. Relative paths are interpreted from the directory in
which the command was entered.

On the first start, MR creates a settings source when none exists. On a
normal Linux account this is $XDG_CONFIG_HOME/mr/settings.mrmac, or
$HOME/.config/mr/settings.mrmac when XDG_CONFIG_HOME is not set. This
configuration directory also contains the default color-theme file, while
personal macros live below its macros subdirectory. These files belong to
the user account; starting MR from another project does not create a
second configuration merely because the working directory changed.

Note: The first start should not require configuration work. Open a file,
use the editor, and change only a setting whose effect you understand. The
defaults are intended to provide a complete usable environment, not an
installation questionnaire disguised as an editor.

.topic UserManualC01S03P01=206
 1.3.1 AN EDITOR WINDOW UP CLOSE

Figure {1.3.1:UserManualC01S03P01} shows an empty zero-length file. The numbered callouts
identify controls which belong to the editor window rather than to the
terminal around MR.

PDF illustration: An empty editor window. Repeated callouts 5 and 6 mark
the two possible scrollbar positions and the two resize handles
respectively.

1. Close. The left control closes the window, not the terminal and not the
file on disk. If the document has unsaved changes, normal dirty-state
handling asks what to do before the window disappears.

2. Window markers. The bracketed marker block reports only states which
currently apply, for example modified text, Git changes, insert mode, word
wrap, language, read-only state, macro recording, workspace-main status,
or background activity. Hovering over a marker explains it. Git and
activity markers can also open their related details.

3. Title and move strip. The bracketed title normally contains the file
path; a document without a persistent name uses ?No-File. Drag an unused
part of the top frame to move the window. The active window has the
emphasized frame and exposes its frame controls; a double-click on the
move strip toggles zoom.

4. Zoom, restore, and minimize. The up control toggles between the
window's ordinary and maximized geometry. The down control minimizes the
window to a one-line entry at the bottom of the desktop. That entry has
its own restore control, which returns the stored normal geometry. Restore
from minimize and restore from zoom are therefore different operations
even though both recover an earlier shape.

5. Automatic scrollbars. The repeated callouts point to the right and
lower edges where vertical and horizontal scrollbars appear. With
Scrollbars set to Smart, as in the figure, an empty document has no useful
range and both bars are absent. A bar appears automatically when content
extends beyond its viewport. Always reserves both bars even when they
cannot yet move; Smart usually leaves more room on a small terminal.

6. Resize handles. Drag either marked lower corner of the focused window
to resize it. Dragging the top frame moves the complete window instead.
With Window Manager enabled, moving a window to a desktop edge can also
snap it to the corresponding half of the usable desktop.

Clicking inside a window selects it. With several windows open, F6 and
Shift+F6 select the next and previous window, while Ctrl+F6 opens the
Window List. When more than one virtual desktop is configured, Shift+F11
and Shift+F12 move the active window to the left or right desktop and
follow it. Ctrl+Shift+F11 and Ctrl+Shift+F12 change only the visible
desktop. The corresponding menu commands and the complete topology model
are described in Chapter {12:UserManualC12}.

Five keys are enough for the first exploration:

F1: opens context-sensitive Help for the current menu or dialog.

F10: activates the menu line. Use the arrow keys and Enter to choose a
command.

F12: opens User Interface Settings in the ordinary editing context.

Esc: leaves the current menu or cancels the current dialog without
accepting its draft.

Tab and Shift+Tab: move between controls in a dialog.

The function-key labels are contextual. If a live label differs from a key
named here, follow the live label: a dialog, tool, or keymap may have
assigned that key another meaning.

.topic UserManualC01S05P01=209
 1.5.1 DESKTOP AND MESSAGES

Window Manager enables MR's assisted mouse movement for desktop windows.
Dragging a normal window to an edge then snaps it to the corresponding
half of the usable desktop; movement away from an edge keeps the window
within the managed bounds. When the option is disabled, dragging uses
TVision's ordinary window behavior. Keep it enabled for the normal
multi-window environment.

The Hero messages group controls performance and progress notices such as
file-load timing and the first minimap rendering. Show on messageline and
Write to log are independent destinations. Turning off Hero output on the
message line does not suppress ordinary warnings, validation errors, or
other operational feedback.

Minimum file size applies to file-size-aware Hero notices before either
destination is used: the file must be strictly larger than the selected
threshold. The slider and editable numeric field share a range of 0--100
MB; changing either updates the other. The MB label represents units of
1,048,576 bytes. Non-file Hero notices, including Macro Brain activity,
are not filtered by this size threshold. Defaults are message-line output
on, log output off, and 8 MB. Invalid numeric input prevents applying the
draft.

Virtual desktops selects between one and nine desktops. One is the
simplest starting value. Additional desktops provide separate views of the
same running application; they do not create independent settings or
duplicate documents. Cycle virtual desktops makes navigation from the last
desktop continue at the first, and vice versa. Leave cycling off if
reaching an end should be an orientation cue.

.topic UserManualC01S05P02=210
 1.5.2 CURSOR

Cursor behaviour has two modes. Bound to text keeps the cursor on
positions represented by the current line and is the conservative choice
for ordinary editing. Free movement permits the cursor to move beyond the
existing end of a short line; inserted text then materializes the
necessary spacing. Free movement is convenient for column-oriented
editing, but it can be surprising before virtual space is familiar.

Cursor position marker controls the compact position text shown in a
window frame. It must contain one R and one C; at runtime they expand to
the current row and column. For example, R:C produces a compact
conventional display, while R/C changes only the separator. The value may
contain at most ten characters.

 1.5.3 OPENING BINARY FILES

Autodetect binary files examines boundary samples when a file is opened. A
file that appears binary is directed to the Bento hex editor rather than
decoded as ordinary text. Keep this enabled unless unusual textual data is
repeatedly misclassified. The explicit Text > Hex editor command remains
available regardless of this option.

.topic UserManualC01S05P04=212
 1.5.4 FILE-COMPARISON LAYOUT

R/O file comparing makes the compare panel read-only. This is the safe
first setting because reviewing a difference cannot accidentally edit the
comparison target. Directional commands can still transfer a selected
change explicitly.

Start configuration chooses which role appears first when a
file-comparison Bento opens: Original <> Compare or Compare <> Original.
It changes placement, not the meaning of either role and not the direction
of an apply command.

The four File compare gutters fields describe the projections before and
after each panel. Every position is blank or one of:

M: minimap;

D: difference marker;

L: line numbers;

C: code-folding marker.

Order is significant. A leading value of LD places line numbers and then
difference markers before the document text; a trailing M places the
minimap after it. Original and Compare have separate leading and trailing
settings so a dense comparison can remain symmetric or deliberately give
one panel more space.

.topic UserManualC01S06=214
 1.6 WHAT IS SAVED, AND WHEN

There are three different things which are easily confused:

1. The compiled application supplies complete hardcoded defaults.

2. settings.mrmac is the canonical persisted bootstrap source for the
user's accepted configuration.

3. The running application holds the authoritative runtime settings after
startup and while dialogs or macros make accepted changes.

At startup, missing known settings receive the current build's defaults.
The resulting complete current-version source is then executed in the
settings context. The runtime model becomes authoritative only after that
succeeds. This is why settings.mrmac is readable MRMAC source but is not
an ordinary startup script to extend casually.

Most accepted setup changes are written through the central runtime
snapshot to settings.mrmac. A normal exit also persists remaining dirty
settings. Some domain dialogs additionally have direct Load, Save, or Save
As commands for portable artifacts. A color theme file contains the
palette values; a keymap file can carry reusable profiles and bindings.
These artifacts are not alternative global settings stores. settings.mrmac
records the active paths and selections, while the named artifact owns its
domain payload.

In particular, changing a palette in Color Setup affects the running
draft. Use Save Theme when those color values must be written to a
reusable theme file. Merely seeing a new color on screen does not turn
inline palette values into entries in settings.mrmac; inline color
settings are not part of that canonical file.

{Up - 1 First Start:UserManualC01}
{Help index:DetailedIndex}

.topic UserManualC01S07=215
 1.7 AUTOEXEC COMES AFTER SETTINGS

The Macro Library's AUTOEXEC list contains macro files below the
configured macro directory. During startup, MR first loads and applies
settings.mrmac; it then runs the configured AUTOEXEC files in list order.
Workspace restoration and command-line files follow afterwards.
Consequently an AUTOEXEC macro can deliberately change runtime behavior
after the persisted settings have taken effect.

PDF illustration: The Macro Library with available macro definitions on
the left and the ordered AUTOEXEC file list on the right. Add only
automation whose startup effects are understood.

MRSETUP itself is reserved for the controlled settings startup and is
rejected in an ordinary AUTOEXEC execution. AUTOEXEC files use normal
MRMAC procedures: for example, they may register menus or bindings, load a
palette, or establish deliberate session behavior. Such a later change may
be a session overlay. SAVE_SETTINGS() persists supported dirty runtime
settings through the central snapshot; domain artifacts still require
their own save operation, and palette values are not serialized inline
into settings.mrmac.

If an AUTOEXEC file is missing or cannot be executed, startup continues.
The failure is written to the startup log and shown with that file in the
Macro Library; the invalid entry is removed from the configured list and
the cleanup is persisted through the normal settings path. This avoids a
modal error on every future start while keeping the loss diagnosable.

Note: Use settings.mrmac for stable accepted configuration, external theme
or keymap files for reusable domain data, and AUTOEXEC for intentional
post-settings automation. Keeping those roles separate makes startup
behavior predictable---and makes later experiments much easier to undo.

.topic UserManualC02S01=218
 2.1 THE DESKTOP, WINDOWS, AND DOCUMENTS

MR starts inside a terminal but does not behave like a single-buffer
full-screen program. TVision supplies a desktop on which editor windows,
Bento workspaces, modeless macro tools, Help, and modal dialogs coexist.

A window is the visible and interactive container; a document is the text
or binary content behind an editor. More than one viewport may refer to
the same document, and a workspace may restore several different documents
and their geometry.

The active window has a highlighted frame. Its title identifies the
persistent file when one exists. Frame markers report properties such as
modification, Git changes, read-only state, insert mode, language,
workspace-main status, macro recording, or background work. Hovering over
an ordinary marker explains it. Hovering over the activity marker opens a
transient list of that window's running work; clicking the marker pins the
list until it is clicked again, closed, or dismissed with Esc. The list
observes work but does not cancel it. Line and column information appears
in the configured cursor-position marker. The editor's left and right
projections can contain line numbers, fold markers, difference markers, or
a minimap.

{Help index:DetailedIndex}

.topic UserManualC02S02=219
 2.2 MENUS AND THE STATUS LINE

The menu line is the complete compiled command map. Press F10 to activate
it, move with the arrow keys, and press Enter to execute a selection. A
highlighted letter is the menu mnemonic. The mouse can also select menus
and buttons when terminal mouse reporting is available.

The status line at the bottom shows the current function-key assignments.
Those labels are contextual rather than decorative. Startup, ordinary
editing, compiler diagnostics, file comparison, Bento panes, and the macro
debugger may assign different meanings to the same function key. When this
manual and the live status line disagree about a function key, the live
status line wins. On terminals that report modifier state, holding Shift,
Ctrl, Alt, or Super changes the displayed function-key bank before a
function key is pressed. Empty positions mean that the current context has
no assignment for that modifier combination. Label changes use the same
short transition language as the message line.

Note: Most commands are reachable through both a menu and a keymap action.
A key shown in a screenshot belongs to the captured profile and context;
it is not a promise that every keymap uses the same sequence.

{Help index:DetailedIndex}

.topic UserManualC02S03=220
 2.3 HELP AND EXPLANATORY MESSAGES

F1 opens context-sensitive Help for the active dialog or menu. Shift+F1
opens the detailed Help index. Inside Help, Tab and Shift+Tab select
references, Enter follows one, and Backspace or Alt+F1 returns to the
previous topic.

MR uses the menu line for transient information as well. Success,
information, warning, and error messages have separate priorities and
colors. Long-running work can post progress without replacing a more
important error. The log window retains diagnostic detail that is too
long-lived for the message line. Use File > Open live log, File > Open
journal, or the configured log viewer when a short notice is insufficient.

.topic UserManualC02S04=221
 2.4 PROGRESS AND PERFORMANCE OBSERVATION

Some foreground batch operations enter Static Mode. The message lane then
becomes a right-to-left progress bar with a centered completed/total
count, ordinary transient messages are suppressed, and the function-key
line changes to Esc Abort. F1 through F12 are disabled immediately outside
Fullscreen; Esc belongs to the active operation. When the operation
finishes or acknowledges cancellation, the previous labels and normal
message animation return.

Help > Performance panel toggles a global diagnostic panel above the
desktop. Its activity meter distinguishes active, queued, and result-ready
work; the text rows show worker, lane, owner, timing, lifecycle, and
selected runtime I/O counters. Use it to explain latency or verify that
work returns to idle. It is an observation surface, not a task manager.
Esc closes the panel.

{Up - 2 Basic Concepts:UserManualC02}
{Help index:DetailedIndex}

.topic UserManualC02S05=222
 2.5 EDITOR MODES

Insert and overwrite determine how ordinary typing affects existing text.
Read-only state prevents text mutation but still permits navigation,
search, copying, and inspection. A binary file may open as a Bento hex
editor instead of being decoded as text. File comparison and compiler
output are also specialized workspaces rather than ordinary editable
buffers.

The editor is UTF-8 capable. Display columns and byte positions are
therefore not interchangeable concepts. Commands operate on the logical
document and the active editor projection; users should avoid treating a
displayed glyph as necessarily one byte or one terminal cell.

{Up - 2 Basic Concepts:UserManualC02}
{Help index:DetailedIndex}

.topic UserManualC02S06=223
 2.6 FULLSCREEN PRESENTATION

F11 gives the selected editor the complete desktop and hides its frame,
the menu line, the function-key line, and the Performance panel. A brief
hint shows the exit keys. F10 exposes the menu temporarily without ending
Fullscreen; F11 or Esc restores the normal layout and the window's
previous bounds. Fullscreen changes presentation, not document or
workspace ownership. It also suspends Static Mode as a user-interface
restriction: Static progress remains recorded for the operation but is not
drawn, function keys remain usable, and Esc leaves Fullscreen rather than
aborting the batch. If the batch is still running afterwards, its normal
Static Mode display resumes.

 3.1 CHARACTER, LINE, AND PAGE MOTION

The arrow keys move by one logical editing position. PageUp and PageDown
move by approximately one viewport. Home and End move to meaningful
boundaries according to the active keymap, while dedicated top-of-file and
bottom-of-file actions are available in the action catalog. Word-left and
word-right use the configured word delimiters rather than an ASCII-only
assumption.

The editor permits horizontal navigation beyond the currently visible
columns. A horizontal scrollbar indicates the projection offset. Very long
lines are not reformatted merely because they do not fit on screen.

Note: Keymap profiles may emulate WordStar, Emacs, Nano, or a personal
scheme. Consequently this manual names navigation actions more often than
fixed sequences. Use Help > Keys and the status line for the current
binding.

{Up - 3 Cursor Control and Navigation:UserManualC03}

.topic UserManualC03S02=227
 3.2 GOING DIRECTLY TO A LINE

Search > Goto line number opens a one-based line-number dialog. The
accepted range is based on the document's known line state. On very large
files the line index may still be completing in the background; MR reports
estimated state until the exact result is available rather than freezing
the editor.

The minimap combines a local text-density projection with a global
position marker. In Braille mode, every terminal row provides four
vertical dot rows. Each dot row samples one source line, while its
horizontal dots summarize the occupied display-column ranges. A minimap
with $R$ rows can therefore show at most $4R$ source lines without merging
them. If a document is longer, the pattern body follows a bounded window
around the active viewport instead of compressing arbitrarily many source
lines into the same Braille dot. Distant lines are then absent from the
pattern body. This preserves useful local shape but means that the body is
not a line-accurate thumbnail of the complete file.

The separate viewport marker remains global: it shows the active
viewport's position within the entire document, independently of the
bounded pattern window. Use that marker and the adjacent vertical
scrollbar for global orientation and distant movement. Search hits,
changed regions, or other overlays can colour the represented minimap
cells.

{Up - 3 Cursor Control and Navigation:UserManualC03}
{Help index:DetailedIndex}

.topic UserManualC03S03=228
 3.3 POSITION MARKERS

Search > Push position stores the current document location on the marker
stack. Search > Get position returns to the most recent valid entry. This
is useful before following a declaration, compiler diagnostic, or search
result. Invalid locations are skipped when their windows or documents no
longer exist.

Random-access marks provide named or indexed destinations where the active
keymap exposes them. They differ from the push/pop stack: retrieving one
does not mean "return to the immediately preceding place." Use the stack
for temporary excursions and random-access marks for landmarks that should
remain available during a longer editing operation.

{Up - 3 Cursor Control and Navigation:UserManualC03}

.topic UserManualC03S04=229
 3.4 MATCHING AND STRUCTURAL MOTION

Text > Match parenthesis (Alt+Shift+P) moves between matching brackets or
parentheses.
Language-aware folding and outline commands provide larger-scale
structural navigation. Their results depend on the detected language and
the current syntax state; plain text remains navigable even when no
structural producer is available.

Fold markers represent collapsible ranges without deleting text. Opening
or closing a fold changes only the projection. Search, save, block
operations, and MRMAC continue to address the underlying document.

activate dialog controls. Exact behavior depends on the terminal emulator
and whether it forwards mouse events. Keyboard navigation remains complete
and is the reliable fallback over remote or restricted terminal
connections.

 4.1 ONE APPLICATION, STAGED CONFIGURATION

MR has no separate setup executable. Setup opens
the configuration areas for colors, keymaps, filename extensions, compiler
profiles, paths, backups, interface behavior, search defaults, and live
logs. Each dialog edits a working draft. Accepting the dialog applies
validated settings. Closing a dirty dialog can request Save, Discard, or
Cancel; explicit load/save operations may already have applied their
changes.

Persisted settings are represented in settings.mrmac. Users should change
them through the dialogs or documented MRMAC settings operations. Directly
editing serialized lines is possible for recovery and review, but it
bypasses field validation and is not the normal setup path.

In a modal dialog, Enter activates its declared primary action when the
current input control does not consume the key. Help remains available
through F1 or its mnemonic; it is not the implicit acceptance action.

.topic UserManualC04S02=233
 4.2 KEYMAP PROFILES

Global main-menu mnemonics require Alt without additional Shift, Ctrl, or
Super modifiers. Explicit command shortcuts with these modifiers remain
available. Alt+P opens Setup; Alt+D opens Debug. The supplied Emacs profile
uses Alt+Shift+D for Delete word forward.

Setup > Key mapping manages profiles and their bindings.
A binding has a context, a target type, a target action or macro, a key
sequence, and a description. Context prevents an editing binding from
silently taking over a dialog or menu. Multi-key sequences are supported
where the resolver and profile define them.

PDF illustration: The Key Manager with WordStar, Emacs, and Nano profiles.
The binding list belongs to the selected draft; Use makes a profile
active.

Use activates the selected profile. Add, Ren, and Del manage profile
drafts; New, Edit, and Delete manage bindings. Load, Save, and Save As
exchange profile files. Capturing a key is safer than spelling a sequence
by hand because Help keys and reserved interactions are filtered by the
capture dialog.

The package installer places the factory files in
$XDG_CONFIG_HOME/mr/macros/keymaps, or in $HOME/.config/mr/macros/keymaps
when XDG_CONFIG_HOME is unset. A factory-new Key Manager opens Load and
Save As in that directory. MRDefaultKeymaps.mrmac is the complete recovery
import: it resets the keymap draft, installs the WordStar, Emacs, and Nano
profiles, and selects WordStar. emacs.mrmac and nano.mrmac reset to and
select the respective single profile. wordstar.mrmac supplies the
three-profile set with WordStar selected and adds Smart Backspace through
wordstar-extensions.mrmac. Loading a file remains an explicit action;
installation alone does not silently replace the active profile.

The current factory WordStar, Emacs, and Nano files all bind Ctrl+A to
Block > Mark all, creating a line block for the complete document. In
particular, the supplied Emacs and Nano profiles no longer use that chord
for beginning-of-line motion. The canonical action is MR_BLOCK_MARK_ALL;
MR_EDIT_MARK_ALL remains an alias for existing bindings. Personal keymap
files are preserved by installation, so inspect or explicitly import the
desired binding in an older setup.

Before changing data: Do not delete or rewrite the only bindings needed to
reach setup until the new profile has been tested. Keep a loadable
known-good keymap file when experimenting with stateful or multi-key
emulations.

.topic UserManualC04S03=234
 4.3 COLORS AND THEMES

Setup > Color setup groups color roles by domain. Each
item-list row begins with a three-column Aa sample rendered in the role's
foreground and background colors. Selection highlighting affects only the
following description, leaving the sample exact and readable. Foreground
and background each have red, green, and blue numeric sliders with the
range 0--255. The centered RRGGBB/RRGGBB value shows the exact 24-bit pair
for the selected role. Both the readout and its Aa sample update
immediately while clicking, dragging, or using the keyboard. Changing
roles retains the component edits already made in the dialog draft. Theme
files can be loaded or saved for reuse. Invalid or missing groups retain
their hardcoded defaults.

Fresh installations use the 256-color palette so that the built-in
BIOS-derived theme retains its ANSI palette-index semantics. The Interface
setup page may instead select 24-bit RGB (automatic). Automatic mode
supplies the stored RGB values to Turbo Vision, which uses true color when
the terminal supports it and its normal fallback otherwise. Palette mode
maps the exact 16 VGA default colors back to their ANSI palette indices,
preserving the terminal's configured classic colors. Other RGB values are
quantized to standard xterm-256 color indices; Turbo Vision performs any
further fallback required by terminals with fewer colors. Thus both modes
share one settings representation and one color draft; there is no
duplicate palette configuration.

.topic UserManualC04S03P01=235
 4.3.1 EDITING AN RGB COLOUR PAIR

Select a group at the top of Color setup, then select a role in its item
list. The six sliders edit the red, green, and blue components of
foreground and background independently. Drag a slider or focus it and use
the arrow keys for steps of one; Page Up/Down changes by 16 and Home/End
selects 0/255. The centred hexadecimal pair is a readout, not an editable
hexadecimal field. The Aa sample uses the current output mode, so a
palette-mode preview can quantize a colour even though the readout retains
its exact RGB value.

PDF illustration: PTY capture of Color setup with 24-bit RGB output
selected. Foreground and background have separate RGB sliders. The
displayed 60D0FF/101020 pair and the text-role sample update immediately,
including while a slider is being dragged.

Choose OK to apply and persist the colour draft. Closing or cancelling a
changed draft asks whether to Save, Discard, or Cancel closing. Load Theme
activates the selected theme immediately and persists its selection; Save
Theme applies the current draft and writes the chosen theme file. These
explicit load/save operations are not undone by later cancelling the
reopened dialog. Changing the output mode itself belongs to User Interface
Settings, under Color Management; the RGB sliders remain available in
either mode.

Filename-extension profiles may select a theme automatically. This allows
a different visual treatment for code, prose, logs, or comparison work
without creating a second global color registry. Distinguish editing a
role in the draft from explicitly activating a theme with Load Theme.

.topic UserManualC04S04=236
 4.4 PATHS

The Paths dialog configures the settings macro, macro directory, Help
file, temporary directory, shell executable, audio player, and log
destination. History limits control the retained file, path, and workspace
entries.

Use absolute paths for infrastructure whose meaning must not depend on the
launch directory. The temporary directory is for disposable products; do
not point it at a source directory. The settings macro path must include a
filename, not merely a directory.

Without a usable remembered directory, ordinary file dialogs fall back to
the user's home directory, then to the working directory. Macro loading
and the pre-save/post-load macro selectors first try the configured macro
directory. These are scope-specific defaults: choosing a macro path does
not change the starting directory of every unrelated file dialog.

.topic UserManualC04S05=237
 4.5 BACKUPS AND AUTOSAVE

Backup policy selects no backup, a sibling backup file, or movement to a
backup directory. Frequency may be first save only or every save. Autosave
can be driven by keyboard inactivity and by an interval; zero disables the
respective trigger.

Workspace autosave is a distinct concern. It preserves window topology and
workspace membership, while document autosave protects changed text.
Restoring one does not imply that every dirty document has already been
written to its persistent file.

 5.1 STARTING WITH FILES

Pass one or more file paths after the executable name:

  ./mr README.md Makefile src/main.cpp

Each readable file becomes an editor window. The last loaded window is
active. Relative paths are interpreted from the launch directory and
normalized before loading.

Shell glob patterns are accepted:

  ./mr '*.md' 'src/*.cpp'

Quote a pattern when MR, rather than the invoking shell, should expand it.
Flat glob loading does not recurse into descendants.

.topic UserManualC05S02=241
 5.2 RECURSIVE LOADING

--load-recursive and its short form -lr enable recursive startup loading.
A directory argument loads readable files below that directory. A wildcard
argument recursively matches below the non-wildcard root.

  ./mr --load-recursive documentation
  ./mr -lr 'src/*.cpp'

Recursive loading can create many windows. Prefer a narrow filespec or a
workspace when the repository contains build trees, vendored dependencies,
or generated output that should not become part of the session.

.topic UserManualC05S04=243
 5.4 STARTUP MACRO AUTOMATION

Advanced workflows may run an MRMAC file after settings, AUTOEXEC macros,
the workspace, and startup files have been loaded:

  ./mr README.md --run-macro=macros/session-start.mrmac

The two-part form is also accepted:

  ./mr --run-macro macros/session-start.mrmac

Multiple options run in argument order. The option --exit-after-run-macro
requests termination after at least one startup macro has been processed.

This facility is useful for deterministic demonstrations, batch-like
editor automation, and test sessions. It still runs through the normal
MRMAC loader and UI-thread execution route; it is not a second command
language.

Results are presented as selectable paths, and Load all opens every

.topic UserManualC06S04=249
 6.4 SAVE, SAVE AS, SAVE ALL, AND REVERT

File > Save writes the current document to its persistent path. File >
Save As chooses another path and updates the window's persistent identity.
File > Save all collects dirty windows and stops if a save is cancelled or
fails.

Alt-X exits through the dirty gate when changed documents exist. Save All
is the primary choice, so a plain Enter saves all eligible documents and
continues the exit. Discard All and Cancel require an explicit selection.

File > Revert reloads the saved file and discards unsaved document changes
after confirmation. It requires a persistent file. A read-only window
cannot be saved as ordinary editable content, although supported log roles
may offer their own snapshot save path.

Before changing data: Revert, closing a dirty window, loading a workspace
over active state, and exiting are dirty-gated operations. Read the
confirmation detail: Save, Discard, and Cancel are intentionally different
lifecycle decisions.

 6.5 RIGHT-CLICK CONTEXT MENUS

.topic UserManualC06S07P01=253
 6.7.1 AUTOMATIC SAVING AND LOADING

Open Window > List. The Auto checkbox button beside Save workspace
controls automatic saving; the separate Auto checkbox button beside Load
workspace controls automatic loading. The two settings are independent and
persist when toggled; [x] means enabled and [ ] disabled.

Autosave records changes to the workspace after a short settling delay
(currently about one second), with a final flush when MR exits. It is
separate from the keyboard-inactivity and interval triggers for document
autosave. Turning workspace autosave off clears the embedded saved
workspace from settings.mrmac; it does not delete already created,
separately named workspace files.

Autoload restores the workspace embedded in settings.mrmac at startup,
after settings and AUTOEXEC macros and before additional command-line
files and startup automation. It does not select the newest timestamped
file from a directory. With Autoload off and a saved workspace available,
MR normally asks whether to Restore workspace, Discard workspace, or
Cancel. Cancel preserves the stored workspace for later; Discard removes
its embedded restoration data. A matching command-line file can restore a
saved single-file workspace directly, and restart after an update can also
force restoration.

PDF illustration: PTY capture of Window List. The two Auto buttons
independently control workspace saving and startup loading; the
neighbouring buttons perform explicit Save workspace and Load workspace
operations.

With workspace autosave enabled, a successful autosave writes a named
snapshot in ~/.config/mr/workspaces/ (or $XDG_CONFIG_HOME/mr/workspaces/):

  .MR autosaved Workspace YYYY-MM-DD HH:MM:SS.mrmac

The leading dot hides these files in ordinary directory listings. Workspace
Load and Save always show hidden files. Their history determines the initial
directory; with no usable history they start in this autosave directory.
The directory is created when needed. Manual workspace saves still use the
filename and directory selected in the Save dialog.

The slider below the workspace buttons in Window > List controls how many
of these files are kept (1 through 50, default 10). After each successful
autosave, older files with this exact naming pattern in the same directory
are deleted, including files from earlier sessions. The timestamp in the
name determines age; the newly saved file is always retained. Other names,
subdirectories, and symbolic links are left untouched. Decreasing the limit
applies on the next successful autosave, not while moving the slider.

The timestamp is local time. Workspace Load and Save histories remember
the result, and the workspace extension in settings.mrmac is also updated.
Use Open workspace or Get Last to select a saved snapshot. The name has
one-second precision, so another write within the same second can reuse
it; these files are not a version-control history or a backup of unsaved
text.

 7.1 INSERT AND OVERWRITE

In insert mode, typed text is added at the cursor and existing content
moves logically to the right. In overwrite mode, eligible existing
characters are replaced. The frame and menu state indicate the current
mode. Edit > Insert toggles it.

New text enters the piece table's add buffer. This implementation detail
is visible to the user only through its consequence: inserting into a very
large file does not require moving all later bytes in memory.

 7.2 LINES AND LINE ENDINGS

Enter inserts a line boundary using the active editor behavior.
Filename-extension settings can require a final line ending, preserve or
normalize relevant conventions, and control the EOF marker. Avoid assuming
that a visually blank final row is the same as a stored final newline.

The CR/LF at EOF and related profile fields describe save policy, not an
extra character painted into the text. File > Info helps distinguish

.topic UserManualC07S03=257
 7.3 AUTOMATIC BRACKET PAIRS

Auto pair brackets in the editor settings of DEFAULT or a matching
filename-extension profile enables pairing for parentheses, square
brackets, and braces. It is off by default. In insert mode, with no text
selection, typing one opening delimiter inserts its closer and leaves the
cursor between them. Typing a closing delimiter already present at the
cursor moves across it instead of inserting a duplicate.

Pairing applies to single-character text input. Overwrite mode, selected
text, and bracketed paste do not use this pairing path. It does not pair
quotation marks or consult syntax to exclude strings and comments.
Matching-parenthesis navigation remains a separate command. The persisted
option is AUTO_PAIR_BRACKETS.

.topic UserManualC07S04=258
 7.4 CLIPBOARD INPUT

Edit > Paste requests text from the system clipboard and inserts it at the
cursor. This remains a clipboard operation when a persistent block exists;
block duplication is the separate Block > Copy block command. Edit >
Append and Edit > Cut and append build a larger clipboard payload from
several blocks. Terminal or operating-system clipboard exchange is
available through the corresponding editor actions and MRMAC primitives.

On Wayland, system exchange requires wl-copy and wl-paste from
wl-clipboard; on X11 it requires xsel or xclip. Supported terminals can
provide clipboard exchange through OSC 52 for remote sessions. The
terminal emulator's own paste command remains an alternative because it
sends text input directly instead of asking MR to read the clipboard.

Pasting into a column or line-oriented workflow should be preceded by a
check of the current block state and insert mode. A persistent block can
remain active after navigation; the highlighted projection is the warning
that the next block-aware command may not act only at the cursor.

.topic UserManualC07S05=259
 7.5 UNICODE INPUT

MR stores and displays UTF-8 text. A character may occupy several bytes,
and a glyph may occupy zero, one, or more terminal cells depending on
Unicode and terminal behavior. Cursor motion, column blocks, and
formatting therefore use editor and display-column rules rather than byte
offsets.

The MRMAC ASCII and Emoji tools can copy a selected character to the
clipboard. They are convenient for characters that are awkward to enter
with the terminal's compose or input method.

 8.1 CHARACTER DELETION

Backspace removes the logical character before the cursor; Delete removes
the eligible character at the cursor. At line boundaries the operation may
join lines. UTF-8 sequences are treated as editor characters rather than a
request to delete one arbitrary byte.

With a visible marked block, Delete removes the block only when the cursor
is inside it. Backspace also removes it when the cursor is immediately at
its right boundary. Outside those positions, these keys delete a single
character in their usual direction and preserve the block marking.

Read-only windows reject mutation. If a delete command appears inert,
inspect the read-only marker, current window role, active block, and
command state before assuming that input was lost.

described in Chapter {11:UserManualC11}. Saving clears the current undo history; closing or replacing the document

 10.1 THREE BLOCK SHAPES

MR supports line, column, and stream blocks. A line block contains
complete logical lines. A column block is rectangular in display
coordinates. A stream block is one continuous range from its start
position to its end position. The distinction determines what copy, move,
delete, indentation, case conversion, and save-block operations receive.

Block > Mark lines, Mark columns, and Mark stream start the respective
mode. End marking commits the current range. Turn marking off removes it.
Hide/show block mark changes only whether the selection is projected; the
block still exists when hidden.

remain live.

.topic UserManualC10S02=274
 10.2 MARKING BLOCKS WITH THE MOUSE

In ordinary editing mode, with line drawing switched off, press the left
mouse button at the start of the desired range, keep it held while moving
to the other end, then release it. The highlight follows the pointer;
releasing the button commits the block. Hold the modifiers before pressing
the mouse button and keep them held until release.

  Block shape | Mouse gesture | Selected range
  Stream | Left-button drag | Continuous text between the two endpoints.
  Column | Alt + left-button drag | Rectangle in display columns and
    logical lines.
  Line | Ctrl+Alt + left-button drag | Complete logical lines from the
    first touched line to the last.

Dragging in either direction is supported. Moving beyond a text-area edge
scrolls the view while extending the mark. Column selection includes the
pointed-to cells at both horizontal ends; a stream selection ends before
its end position. Tabs occupy their configured display width.

Ctrl + left-button drag explicitly starts a new stream block. Use this
when the drag starts inside an existing block: an unmodified left-button
drag there moves that block instead. During a move, a preview follows the
mouse; release places the block, Esc cancels, and a completed move is one
Undo step. A plain right-click opens the context menu.

The terminal must forward the mouse events and modifier keys to MR. If the
terminal or window manager intercepts a gesture, use the corresponding
Block > Mark lines, Mark columns, or Mark stream command.

.topic UserManualC10S03=275
 10.3 MARKING STATE AND CURSOR MOTION

An actively extending block and a committed block are different states.
Cursor motion extends an active selection. After commit, ordinary cursor
movement may preserve or clear it according to the persistent-block
setting. Block > Persistent blocks reports and changes that runtime
policy.

The current block is a first-class editor state. A command may act on it
even when the cursor has moved away or the visible highlight has been
hidden. Before a destructive block command, verify the marked shape and
endpoints.

Before changing data: Hidden selection is not absent selection. If a copy,
delete, format, or case conversion affects more text than expected, turn
block visibility on and inspect the persistent-block state.

Block > Copy inserts a copy at the command's destination while retaining
the source. Move transfers the range. Delete removes it. Equivalent
Edit-menu commands use the clipboard when appropriate.

Every successful mutation enters undo history as an editor operation. A
large block does not need to be flattened into a second complete document
merely to be moved; the piece-table model can express changes as new
ranges and references.

 10.5 INTER-WINDOW TRANSFER

Block > Window copy and Window move explicitly transfer between editor
windows. The target must support the requested mutation and must remain
valid throughout the operation. A read-only or specialized target may
reject the transfer.

Use ordinary clipboard copy when the destination is outside MR or when the
transfer should survive closing the source. Use the window commands when
the relationship between two managed editor windows is the important part.

.topic UserManualC10S06=278
 10.6 INDENT, UNDENT, AND TRANSFORMATIONS

Block > Indent and Undent operate on selected lines using the configured
indentation policy. A stream block is first converted to a line block
covering the touched lines. For a line block, the least-indented nonblank
line determines the movement to the next or previous tab stop, and the
same shift is applied to all nonblank lines. Their relative indentation is
preserved; whitespace-only lines are left alone. Column blocks retain
rectangular semantics. Text > Upper case and Lower case transform the
applicable marked text. Code formatting may consume the block or the whole
file according to the formatter command and profile.

Column-block sorting is available through its command or keymap action.
The sort key is the selected rectangular slice, while complete
participating lines remain the records being reordered. Confirm tab and
display-column interpretation before sorting mixed-width data.

 10.7 LOADING AND SAVING BLOCKS

Block > Load block inserts text read from a file at the block position.
Save block writes only the marked range. These commands are useful for
reusable fragments and for exchanging data without replacing or saving the
whole document.

A saved block is plain selected content, not a workspace or editor-state
serialization. Its block shape, cursor location, theme, and profile are
not encoded in the block file.

 11.1 DOCUMENT-LOCAL HISTORY

Undo and Redo traverse the active editor's change history. Each document
owns its history; changing windows changes which history the commands
address. Read-only views can be navigated but do not gain a mutation
history merely because Undo is invoked.

An undo entry represents an accepted editing operation, not every internal
piece-table step. Text insertion, deletion, block operations, formatting,
and supported macro edits therefore reverse at meaningful editor
boundaries.

 11.2 TRAVERSING THE HISTORY

Edit > Undo moves one step toward the earlier document state. Edit > Redo
reapplies a step that was undone. A new mutation after Undo normally
establishes a new forward history; do not assume that the abandoned redo
branch remains selectable.

Watch the modified marker while traversing. Returning to content equal to
the last saved snapshot can clear the dirty relationship even though the
document has a non-empty history.

.topic UserManualC11S03=283
 11.3 UNDO AND LARGE FILES

The document model stores snapshots and piece relationships rather than
copying the entire file for every operation. This makes practical undo
depth possible even when the original mapping is large. It does not make
history free: inserted text, metadata, and retained snapshots still
consume memory.

Background syntax, folding, minimap, or line-index results are derived
state. When Undo changes the document version, stale results are rejected
and fresh work is scheduled. Undo therefore restores document semantics;
derived projections catch up without owning the edit.

{Up - 11 Undo and Redo:UserManualC11}
{Help index:DetailedIndex}

.topic UserManualC11S04=284
 11.4 UNDO VERSUS PERSISTENT RECOVERY

Undo exists only in the running document lifecycle. Backups, autosave, and
version control protect different time horizons. Closing a document,
restarting MR, or reverting from disk is not a substitute for explicitly
saving an important state.

Note: For risky transformations, combine a saved file or version-control
checkpoint with Undo. One protects the persistent baseline; the other
supports rapid in-session experimentation.

{Up - 11 Undo and Redo:UserManualC11}
{Help index:DetailedIndex}

.topic UserManualC11S05=285
 11.5 MACROS AND UNDO

MRMAC editor procedures route mutations through the same editor model. A
macro can group work according to its operations, and the user can undo
accepted changes. A macro that performs external I/O, launches a process,
or changes settings cannot make those external effects disappear through
text Undo.

.topic UserManualC15S06=312
 15.6 MULTIPLE-FILE SEARCH

Search > Multiple file search selects filespec, root, recursion, search
text, matching rules, editor-window inclusion, and optional workspace
restriction. The request is immutable after submission and runs in the
background. Collection initially reports an open-ended count; once the
candidate set is known, the progress display reports files searched
against the total. The Search button becomes Cancel while the operation is
running. A cancelled or stale partial result is not opened as a valid
Found List.

workspace limits candidates to the active workspace. Whole-word mode takes
precedence over regular-expression mode when both controls would otherwise
be selected. These options are independent: including loaded windows adds
their current in-memory snapshots, whereas workspace restriction limits
the candidate population to workspace members.

opens each distinct result file without treating every match as another
file load.

.topic UserManualC15S07=313
 15.7 MULTIPLE-FILE SEARCH AND REPLACE

The replace variant adds replacement text, review actions, and Keep all
files open. Results are collected before UI adoption. Review permits
Replace, Replace All, and Skip. Files need not all remain open unless that
option is selected.

Replace All applies one replacement per dialog event and shows
completed/total progress. Cancelling pauses mutation and offers Continue,
Abort, or Revert. Continue resumes. Abort keeps the completed prefix as
ordinary Undo records. Revert restores the pre-operation snapshot of every
file touched by that Replace All run; it does not discard unrelated
earlier edits.

Workspace restriction is especially useful in repositories with vendored
or generated trees. A filespec alone describes names; workspace membership
describes the intended project set.

.topic UserManualC18S02=328
 18.2 ENTERING VALUES

The digit buttons enter a value in the current base. Base cycles through
decimal, hexadecimal, and binary representation while preserving the
numeric value.

Hexadecimal output uses a leading dollar sign, for example $2A. The
buttons A through F are accepted only in base 16. In binary mode, only
zero and one are valid. +/- changes the sign of the current input; Clr
clears the input and clears memory when the displayed value is already
zero.

If a stream or line block contains a valid decimal integer when the
calculator opens, that number seeds the input. Whitespace is ignored for
this purpose. Column blocks and non-numeric selections are left untouched
and the calculator starts at zero.

Xor operate bitwise on integer operands.

The interaction follows a conventional accumulator:

1. enter the first operand;

2. choose an operator;

3. enter the second operand;

4. choose another operator to continue, or = to display the result.

The calculator rejects division by zero, invalid digits for the selected
base, and malformed pasted input. A rejected operation leaves the dialog
open so the value can be corrected.

the input display.

and closes the calculator. This is a document edit and participates in
normal Undo and Redo. In hexadecimal mode the inserted text includes the
dollar prefix; change the base before pasting if the destination expects
another notation.

Note: The calculator is an integer tool, not a floating-point expression
evaluator. For repeatable calculations embedded in an editing workflow, an

 19.1 ASCII AND LATIN-1

Tools > ASCII table, normally bound to Alt+Shift+A, opens a modeless
table. Each row contains the visible form, its decimal code, and the range
name. Codes 0 through 127 are the ASCII range; codes 160 through 255 are
presented as Latin-1. The unused C1 interval from 128 through 159 is not

Control codes receive readable labels. For example, code 1 appears as ^A,
space appears as SP, delete as ^?, and non-breaking space as NBSP.

PDF illustration: The modeless ASCII and Latin-1 table; the decimal code
is shown beside each character.

Choosing an entry copies the corresponding character to the system
clipboard and closes the table. Paste it with the active keymap's
clipboard command. The selected row is remembered when the table is opened

 20.3 THE MINIMAP

the editor viewport without changing the document.

 21.2 IDENTITY AND MATCHING

matching.

 22.1 AUTOMATIC INDENTATION

Smart indentation derives the leading whitespace for a new line from the
active language and nearby structure. The filename-extension profile
selects the relevant indentation behavior, while User Interface Settings
offers an indent-style preview.

Automatic indentation is assistance, not a parser rewrite. It acts at the
editing boundary and leaves already existing lines alone. This matters
when opening generated code, patches, or files whose local style
intentionally deviates from the project default.

{Up - 22 Indenting Styles:UserManualC22}
{Help index:DetailedIndex}

.topic UserManualC22S02=348
 22.2 TABS, SPACES, AND VISUAL COLUMNS

An indentation policy must distinguish three concepts:

- the number of visual columns in one indentation step;

- whether newly produced indentation uses tabs, spaces, or a defined
combination;

- the display width assigned to an existing tab character.

These values often coincide in simple profiles but they are not
equivalent. Changing tab display width can change alignment on screen
without changing a single byte. Replacing tabs with spaces changes the
document and should be a deliberate formatting operation.

{Up - 22 Indenting Styles:UserManualC22}
{Help index:DetailedIndex}

.topic UserManualC22S03=349
 22.3 INDENTING AND UNDENTING BLOCKS

Block > Indent and Block > Undent adjust the lines intersecting the
selected block by a shared shift to the next or previous tab stop, based
on the least-indented nonblank line. A stream block becomes a line block
covering its touched lines. Relative indentation is preserved,
whitespace-only lines are unchanged, and column blocks retain rectangular
semantics.

Undent removes only eligible leading indentation. It does not delete
arbitrary non-whitespace text to force a visual column. The operation is
undoable as a document edit.

{Up - 22 Indenting Styles:UserManualC22}
{Help index:DetailedIndex}

.topic UserManualC22S04=350
 22.4 LANGUAGE-SENSITIVE STRUCTURE

For brace-oriented languages, smart indentation observes opening and
closing structure. For indentation-oriented languages, leading whitespace
itself is semantically significant and deserves more caution. Macro
sources, shell languages, markup, and plain text each have distinct
structural cues.

When imported text has mixed indentation, first inspect tabs visibly and
select the correct profile. Repeatedly pressing Indent to make the screen
look right can preserve hidden inconsistencies. Use Re-format code with the appropriate
language and indentation settings, then review its result.

Note: If an indentation result is surprising, check the active
filename-extension profile before changing global settings. A local
profile mismatch is much more common than a universal indentation rule
suddenly becoming philosophical.

 23.2 CODE FOLDING AND OUTLINES

Folding regions reflect structural constructs appropriate to the language:
functions, types, sections, macro bodies, build targets, markup elements,
or indentation scopes. Fold-level commands provide a coarse overview;
individual gutter controls expose local structure.

functions, methods, types, modules, sections, and other structural kinds.
After edits, allow the derived state to catch up before assuming that a
temporarily absent entry has been deleted from the document.

.topic UserManualC23S03=354
 23.3 PARENTHESES AND STRUCTURAL NAVIGATION

Text > Match parenthesis (Alt+Shift+P) moves between a supported matching
pair near the cursor: parentheses, square brackets, or braces. It starts at the cursor
or immediately before it and counts nesting of the chosen delimiter pair.
This is character-based matching; it does not exclude strings or comments.

Search markers, compiler diagnostics, fold outlines, and the marker stack
provide complementary navigation. Use the narrowest semantic operation
available: a diagnostic command for a compiler error, matching for a
bracket, and search for textual occurrences.

.topic UserManualC23S04=355
 23.4 FORMATTING SOURCE CODE

Text > Re-format code recalculates leading indentation in the selected
lines, or in the whole file when no selection or block is active. It uses
MR's built-in indentation rules for the active language and style; it
does not invoke an external formatter or rewrite language syntax.

For C and C++, preprocessor directives and their continued lines remain
unchanged. They do not contribute to the indentation of following code.

Check the active profile and selected scope first. Review the result and
use Undo before saving if the indentation does not match your intent.

.topic UserManualC23S05=356
 23.5 COMPILER PROFILES AND DIAGNOSTICS

Debug > Build current file chooses the compiler profile associated with
the active file. A compiler profile describes the executable, toolchain,
version and target constraints, build flags, include and library
arguments, runtime paths, a pre-build shell command, build-succeeded and
build-failed shell commands, and optional pre- and post-build MRMAC hooks.
Separate success and failure audio paths can announce the result through
the configured audio player.

Setup > Compiler profiles exposes these fields and the
Automatic Setup action. If the selected profile names an executable,
Automatic Setup resolves and probes it, then fills toolchain, version,
target, default flags, include paths, library paths, and runtime paths.
With no executable selected, the action discovers supported compilers on
PATH and inserts or selects matching profiles. The result remains an
ordinary editable profile; automatic setup neither discovers a whole build
system nor hides its decisions.

The pre-build MRMAC hook runs before the external build is submitted. The
shell pre-build command can stop the build with a failing status; the
matching success or failure command then follows the compiler result.
Completion audio and the post-build MRMAC hook are adopted with the final
result. Build context values identify the source, output, profile,
toolchain, and exit status to hooks without requiring them to reconstruct
the command line.

Debug > Next compiler error and Previous compiler error navigate adopted
diagnostics. User Interface Settings controls whether warnings and notes
are tracked in addition to errors and how diagnostic messages are
presented. The minimap can provide long-range orientation, but the
diagnostic navigation command remains authoritative for the next adopted
location.

.topic UserManualC23S06=357
 23.6 DEBUGGING COMPILED PROGRAMS WITH GDB

The compiled-program debugger uses GDB and is separate from the MRMAC
macro debugger. It supports the GDB-compatible compiler profiles for C and
C++, Rust, Go, Free Pascal, and FreeBASIC. Automatic compiler discovery
includes C GCC/Clang, Rust, Go, and Free Pascal profiles with Debug,
Normal, Speed, and Size flavours in addition to the existing toolchains.

To start a session:

1. Install GDB and ensure gdb is available on PATH.

2. Associate the named source file with a compatible compiler profile
whose name or ID contains Debug. Check its debug-information flags.

3. Save and build the file with that profile. The expected output must
exist, be executable, and be at least as recent as the source.

4. Choose Debug > Debug current file, or press Alt+F9. The command is
enabled only while an editor with a recognized source language is focused.
Starting the session also checks the source, profile, and build artifact. An unavailable command is a reason to check the profile,
unsaved source, and build output first.

The editor becomes a debugger Bento with source, Debugger Output,
Variables, Watches, and Program Terminal panes. Startup runs to the first
code line. Program Terminal is the debugged program's terminal, including
keyboard input; Debugger Output carries debugger status and diagnostics.

While a GDB debugger is active, the function keys have these meanings:

F4: Evaluate or assign an expression using GDB semantics.

F5: Continue a stopped program, or request a pause while running.

F6: Run to the source location at the cursor.

F7 / Shift+F7: Add a watch / remove a watch by object or expression.

F8: Stop the GDB session.

F9: Toggle a breakpoint at the cursor's source line.

F10: Step into; F11 steps over; Shift+F11 steps out.

These keys replace their normal editor meanings in debugger context;
outside that context, for example, F9 remains Build current file.

Double-click with the left mouse button in the line-number gutter to set
or remove a breakpoint on that line. This is the mouse equivalent of F9,
and works in both GDB and MRMAC debugger source views while their debugger
controls are active. The line-number gutter must be visible; this is not a
click in the folding gutter. Folded viewport rows are mapped to their
document lines. Breakpoint acceptance still depends on the debugger: GDB
resolves compiled source locations, while MRMAC requires a debuggable
span.

 23.7 GIT STATUS AND FILE CHANGES

For a named file in a Git work tree, MR probes the file's status in the
background. The frame displays its Git changes marker when the file
differs from the repository state or is untracked. Hovering explains the
marker; clicking it is equivalent to Debug > Git changes.

compared with an empty source. The command does not stage, commit, switch
branches, or maintain a second repository model; use normal Git tools for

 24.1 WHAT MRMAC CONTRIBUTES

MRMAC is the integrated macro language for editor automation and runtime
UI extension. Its compiler runs in memory and supports both precompiled
and on-demand macro files. A macro can edit text, inspect editor state,
register menu items and keys, construct dialogs or modeless tools, start
asynchronous work, and cooperate with the application's window system.

The calculator and character tables in Chapters 17 and 18 are concrete
examples: they are application-quality utilities implemented as macros,
not hard-coded simulations in this manual.

.topic UserManualC24S02=364
 24.2 MACRO FILES AND DEFINITIONS

A source begins with a macro-file identity and contains named macro
definitions. The Macro Library indexes those definitions independently of
their key bindings. One file can therefore provide several commands,
shared helper routines, and a startup registration macro.

Use Macro > Macro Library to create, inspect, copy, delete, edit, bind,
play, or debug indexed definitions. The editor provides syntax
highlighting, folding, and outline support for .mrmac sources just as it
does for other supported languages.

{Up - 24 The MRMAC Interface:UserManualC24}
{Help index:DetailedIndex}

.topic UserManualC24S03=365
 24.3 EXECUTION CONTEXTS

A definition declares the context from which it may run. Editor procedures
operate through the current macro/editor linkage; application procedures
can address wider runtime facilities. A window may be explicitly linked or
unlinked through the Window menu for procedures that need an editor
target.

Macro execution is scheduled alongside interactive work. Long-running
operations should use the language's cooperative facilities and explicit
asynchronous interfaces instead of blocking the UI. Multiple jobs may be
active, but shared document and UI effects still require deterministic
ordering from the macro author's point of view.

{Up - 24 The MRMAC Interface:UserManualC24}
{Help index:DetailedIndex}

.topic UserManualC24S04=366
 24.4 MENUS, DIALOGS, AND MODELESS TOOLS

Runtime menu registration adds commands owned by the defining macro. A
conventional macro dialog is assembled, executed, and read as one
interaction. A modeless macro tool stays on the desktop and can receive
subsequent events while other windows remain usable.

Labels in a macro-created UI describe the macro's contract; MR does not
invent semantics for them. Use the context Help available to the runtime
UI where supplied, and consult the owning macro when a command is project
specific.

.topic UserManualC24S05=367
 24.5 KEYS, RECORDING, AND AUTOEXEC

MACRO_TO_KEY and the Key Manager associate a macro definition with a key
sequence and dispatch context. The Macro Library exposes the same
relationship at a user level. Recorded keystroke macros become ordinary
source definitions and can be refined after recording.

AUTOEXEC membership identifies macro files that run during startup. It is
appropriate for menu registration, stable bindings, and deliberate session
initialization. It is not a substitute for settings persistence, and
startup macros should not silently rewrite unrelated configuration.

 24.6 RUNNING A MACRO FROM THE COMMAND LINE

The command-line option --run-macro=FILE loads and executes a macro after
application startup. It is useful for repeatable demonstrations, project
entry actions, and controlled automation. The ordinary application
environment still applies: the named file must be readable, any required
editor target must exist, and errors are reported through the normal macro
runtime.

This manual's screenshots use that mechanism to open deterministic UI
states inside real PTY sessions. The resulting dialogs were not painted
into the images afterward.

evaluation, and execution state are intended for authored logic whose
behavior cannot be understood from one playback.
